# Project identity

A web-chat project's **identity** is what the topbar's lockup, the tab and the
phone show for it: a **name** (the folder's, until one is set), a **logo** (any
shape, beside the name), a **favicon** (square, for the tab and the home-screen
icon), an optional **dark variant** of each image, and whether the name shows
beside the logo (**show-name**, off for a wordmark that already spells it).

All of it is set on this machine with `claude-web-chat identity`. The work —
cropping, keying the background, finding a pixel-art grid, padding, resampling,
making a dark variant — is in the CLI. Your part is the judgment: looking at the
artwork, agreeing the choices with the user, and showing them the candidates.
**Agree each step with the user before you run a command**: nothing here asks
for confirmation itself.

Start with `claude-web-chat identity show`. It prints the name and where it comes
from, each image with its type, size, aspect ratio and bytes (or `none`), which
image the **mark** resolves to (what the phone's topbar and the tab's favicon
draw: the favicon, else a square logo, else none and web-chat's W in the tab),
whether that mark has a dark variant, show-name, and which mode each place
follows: the topbar follows web-chat's ◑ mode, the tab's favicon the browser's
colour scheme. It reports `corrupt` when `.web-chat/project.json` cannot be read.

## The company logo is not the project's

The mark left of the lockup's divider is the **theme's** company logo, not part
of the project's identity. When the user wants that one changed, point them at
**Settings → Brand** while that theme is active. Never store a theme's mark as
the project's logo.

## Name steps

1. **Show** the current name and its source (`identity show`).
2. **Agree** the new name with the user. Keep it short: the lockup and a phone
   screen are narrow, and the tab title truncates. Offer a shorter form when it
   is long (the limit is 64 characters; line breaks and invisible characters are
   refused).
3. **A wordmark?** If the logo already spells the name, decide with the user
   whether to hide the text name: `claude-web-chat identity show-name off`.
4. **Apply**: `claude-web-chat identity name "Acme Web"` (or
   `identity name --reset` for the folder's name again).
5. **Confirm where it shows**: the topbar lockup and the tab title
   (`Acme Web — web-chat`). In this release `claude-web-chat ls`, `status`, the
   remote portal's picker and the Sessions panel keep the folder's name, so do
   not promise those.

Never rename the project's folder: that is a different, rarer operation, and
not this skill's.

## Image steps

1. **Find the file and look at it.** Note its aspect ratio; whether it is a
   mark (a symbol), a wordmark (text), or both; whether it is pixel art or
   smooth; and its background (transparent, a flat colour, or a photo).
2. **Square, or nearly?** One image serves as the logo and the favicon: set it
   as the logo and it is also the mark (the phone and the tab draw it). Content
   within 1.25:1 is padded to an exact square.
3. **Wide, or a wordmark?** Set it as the logo, then settle the favicon with the
   user. Offer the choices, with a `--dry-run --preview` of each where it applies:
   - a separate square image the user supplies (`identity favicon <square file>`);
   - keep web-chat's W as the favicon (set nothing);
   - only for a logo up to 1.25:1: pad the whole logo to a square
     (`identity favicon <file>`; warn that text is unreadable at 16 px). A logo
     wider than 1.25:1 cannot be padded — the CLI refuses it as a favicon and has
     no option to pad it — so for one, offer only the first two.
4. **Does the logo contain the name?** Ask whether to hide the text name
   (`identity show-name off`).
5. **Check contrast in both modes.** The topbar is light in light mode and dark
   in dark mode, so a dark mark on a transparent background can vanish in dark
   mode. Offer the tile (`--background tile`, or `tile:#rrggbb` for a colour of
   the user's choosing) and, where the mark vanishes on the dark topbar, a dark
   variant (`--dark auto`, generated by swapping the artwork's two dominant hues,
   or `--dark <file>` from the user's own artwork). Show the original and the
   generated variant side by side for the user to pick. When the CLI says the
   artwork has no two dominant hues, there is no automatic variant: offer the
   tile or a file of their own. An SVG is never rasterised, so it has neither a
   tile nor an automatic dark variant — only `--dark <file>` gives it one.
6. **Show the candidates on the surface** and let the user pick:

   ```
   claude-web-chat identity logo <file> --dry-run --preview --dark auto
   ```

   The CLI posts one pane, `identity-preview`, itself: each candidate
   (transparent, tile, and their dark variants) at 16, 20, 24 and 32 px on a
   light and a dark ground, beside a mock tab and, for a logo, the topbar
   lockup. Each **Use this** button writes the signal `identity_pick`
   `{seq, kind, background, dark}`, which reaches you when the user presses
   **Push** (P). Tell the user that. It needs a running surface
   (`claude-web-chat open`). `--dry-run --out <dir>` also writes every candidate
   into a directory outside `.web-chat/` for a closer look.
7. **Apply the pick** with the CLI, light then dark in one command:

   ```
   claude-web-chat identity logo <file> --background <transparent|tile[:#rrggbb]> [--dark <auto|file>]
   claude-web-chat identity favicon <file> [the same options]
   ```

   A run without `--dark` that changes the image removes its old dark variant
   (it was made for the old image); the CLI says so.
8. **Verify** the topbar lockup and the phone's mark in both modes (the ◑
   toggle), and the tab's favicon in a light and a dark browser. Tell the user a
   browser may keep showing the old favicon until a hard refresh.

To take something away: `claude-web-chat identity clear logo|logo-dark|favicon|favicon-dark|name|all`
(a light image takes its dark variant with it; `all` clears the four images and
the name, and shows the name again).

## Rules

- **Never send the image anywhere else.** It goes from the user's file to the
  CLI and into this project's `.web-chat/`, nowhere more.
- **Never paste image data into a `render` call.** The CLI posts the preview
  pane itself with the exact bytes; hand-copied base64 has arrived corrupted.
- **Never upscale smooth artwork past its native size without saying so.** The
  CLI notes it when it does (`upscaled from N px`); pass that on, and suggest a
  larger original.
- **Keep the user's file untouched.** The CLI only reads it; never edit, move,
  convert or overwrite it yourself. For a format the CLI refuses (a JPEG, say),
  pass on its conversion hint, which writes a new file beside it.
- **Never rename the folder.**
