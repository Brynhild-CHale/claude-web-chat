# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Changed

- **A service's consent no longer depends on how its pane was rendered.** The trust key covers (project root, `service.js` contents, params), and "params" now means the params the *service* gets: the three keys the shell reads for itself — `form_reset`, `routing`, `signals` — are stripped before the fingerprint, since they say how a render behaves and nothing about the host process. Re-rendering a service-backed pane with `params.form_reset:true` used to restart its child and ask you to approve a service that had not changed. **You will notice two things, once:** a pane whose params carried one of those keys asks for approval one more time after upgrading (a narrow echo of the 0.7.0 re-trust, upgrade step 3 — approve it and it stays approved), and `service.js` receives `ctx.params` without those keys (the pane script still sees them).
- **`claude-web-chat trust <name>` decides one request, and says which.** The supervisor keeps `file-editor` fenced and `file-editor --unfenced` apart precisely so one approval cannot cover the other, but the by-name path recorded a decision for *every* pending request under that name, printed none of their params, and asked nothing — so a pane that mounted a component a second time with params of its own could ride along on the approval you meant for the first. A name matching more than one waiting request now prints each of them and refuses, and you pick one with `--params-fp <fingerprint>` (the listings print it; the full trust key works too) or take them all with `--all`. `--all` given a name is scoped to that name instead of every service on the machine, and a grant now names the params it granted.
- **Capture profiles get `listItems` on their injected helper kit.** A profile bundle lives outside the package and cannot `require` into it, so the bundled reddit extractor carried its own copy of the own-`<li>` list walker — the copy the ctx kit exists to prevent, and the one place the nested-list fix (a nested item emitted twice: once absorbed into its parent's bullet, once on its own) sat with no test pinning it. `listItems(el)` now rides `extract({...})` and `render(distilled, ctx)` alongside `esc`, `collapse`, `safeHref` and `absolutize`; use it instead of `querySelectorAll('li')` when flattening a list. No distillate bytes change for any profile.

### Security

- **The tab-stream extension stops replicating your capture token to your Google account.** The token is the only authentication on the capture path and it is a secret about one machine, but it lived in `chrome.storage.sync` alongside the endpoint and profile preferences — so Chrome uploaded it and pushed it to every profile signed into the same account. It now lives in `chrome.storage.local`; a token an older build synced is adopted onto this machine and removed from sync the first time the extension reads its config, so nothing needs re-entering. **You may notice** the token no longer appears on your other browsers: set it there once, per machine.

### Fixed

- **A long turn no longer loses its work to a graph click.** A turn holds a lock so a click on the graph cannot move the commit point out from under it, and that lock goes stale after a while so a turn that dies without finishing cannot wedge the graph forever. But nothing restarted the clock while the turn was working, so the window was measured from the moment the turn began — and for a turn started by a Push (three minutes) an ordinary long turn outran it, after which the next click on a node discarded everything it had rendered, uncommitted and with no undo. Two changes: Claude's own writes now restart the clock, so a working turn keeps its lock however long it takes (a pane driven by a service component does *not* — its writes must not hold a lock open); and if a stale lock is taken anyway, the abandoned turn's panes are committed as a `preserve` node first, the same way editing a form on an older node preserves what was on screen. **You may notice** an extra node in the graph after a turn that was interrupted; it holds work that used to vanish.
- **A catch-up cursor from before a restart is now reported as a gap.** Event sequence numbers begin again at 1 each time the daemon starts, so a cursor held across `claude-web-chat restart` (or a crash, or a self-update) sits above everything in the new log. `get_events({since})`, the browser's reconnect catch-up and a driver's `getEvents` all read that as "nothing has happened since you last looked" and carried on, while the tool's own description promised a gap whenever a cursor stopped being usable. Such a cursor now answers `gap:true` with `reset:true` (and no `dropped` count, which is unknowable across a boot), so anything that already resyncs on a gap does the right thing; the SSE `gap` frame carries the same marker.
- **A push in flight when the channel drops is redelivered the moment it reconnects.** A Push fired at a live channel is held until the bridge confirms delivery, and a reconnecting bridge is supposed to fold that un-confirmed push back in and redeliver it. It only did so when something else was *also* waiting to be delivered — so in the exact case the fold exists for (the stream died with a push in flight and nothing parked behind it), the push instead waited out a 20-second timeout and arrived attached to your next typed message. It now redelivers on reconnect, and the redelivery is itself held for confirmation, so a second drop is still recoverable rather than silent.
- **"Channel: connected" now means the same thing as a Push does.** The queue panel, `claude-web-chat status` and `init` read one endpoint to say whether a Push wakes Claude, and it answered with the raw count of open wake streams — not the liveness test the push itself uses, which also requires a fresh heartbeat. A half-open stream (a laptop that slept, a Claude Code session that died without closing its socket) therefore showed "channel: connected — a Push wakes Claude now" and hid the parked-delivery notice, while the very next Push parked. Both now use the same predicate; the raw stream count is still reported as `wake_consumers` for diagnostics.
- **The first turn after the daemon starts now commits its own node.** When no daemon was running, the turn-begin hook had nothing to lock — so a turn whose first tool call started the daemon and rendered ended with nothing committed, and its panes sat uncommitted until the *next* prompt's turn-end swept them up and stamped them with that prompt's text. That work now commits at the end of the turn that did it, as a node whose trigger reads `unlocked-turn` and carries no prompt (because there was no lock to read one from). A turn that changed nothing still commits nothing.
- **A push is only confirmed “delivered” once it has actually been sent.** The channel bridge acked a wake the instant it *called* the notification, but that call is asynchronous — a closed transport or a failed write arrives as a rejected promise, never as a throw — so a push that never left the process was still acked, and the ack is what tells the daemon to drop the batch it was holding for you. The ack now waits for the send to settle and is skipped when it fails, so the queue rail times out and offers Retry / Hold instead of showing “Delivered ✓” for something Claude never received.
- **A pane theme supplied on a render is sanitized like every other theme.** `POST /api/render` accepts a `theme`, and it was the one door onto a pane's theme that skipped the theme engine's normalizer: token names that are not `--wc-` prefixed were kept, and values kept the structural characters that let a token break out of its own `name: value;` declaration — while the same theme sent to `POST /api/theme` was cleaned. (`GET /api/theme` normalizes on the way out, so the read side always looked right.) A render's theme now takes exactly the path `set_theme {scope:'pane'}` takes. Omitting `theme` still keeps the pane's current one and sending `null` still clears it; raw `css` at pane scope is unchanged — it remains the documented escape hatch, scoped to that pane's shadow root.
- **A capture over a locked pane says so instead of reporting a clean success.** `POST /api/capture` writes the record and bumps the `tab_capture` signal whatever happens to the pane, but the pane write is a soft-reject when the user has locked that pane — and the route dropped that verdict, so the extension showed a successful capture over a pane that never updated with nothing anywhere explaining why. The response now carries a `pane` field: `'rendered'`, `'not-requested'` (the caller passed `render:false`), or the refusal envelope itself (`{rejected, locked, id, hint}`). Additive on the wire; a caller that does not know the field ignores it.
- **`/api/embed-check` recognises the fully-qualified spelling of `localhost`.** `http://localhost./` (and `http://foo.localhost./`) missed the name check, so the refusal came from the DNS-time filter instead of the cheap first pass. The fence held either way; the first layer now holds on its own.
- **`/api/embed-check` refuses a loopback or private address wrapped in a NAT64 prefix.** The v6 fence decoded only the `::ffff:` v4-mapped prefix, so `http://[64:ff9b::7f00:1]/` — the RFC 6052 well-known prefix wrapping `127.0.0.1` — read as a public host on a machine with NAT64 connectivity. The well-known prefix and the deprecated v4-compatible `::a.b.c.d` form are now decoded to the v4 address they carry, the RFC 8215 local-use prefix `64:ff9b:1::/48` is refused whole (its embedding length is not knowable), and a dotted v4 tail is folded into hextets inside the address expander so every spelling takes one path instead of a shortcut of its own.
- **`diff_nodes` no longer drops a store key named `toString`, `constructor` or `valueOf`.** The store diff asked `key in other` rather than `Object.hasOwn`, and the store is a plain object, so a key sharing a name with an `Object.prototype` member read as present on both sides: it was not reported as added, and the other loop never reached it either, so it vanished from the diff instead of showing up wrong. The theme-token diff used the same test and is fixed with it (no token can collide today — every one is `--wc-` prefixed — but the loop no longer depends on that).
- **A long-lived graph no longer breaks the graph viewer, `get_graph` and `export` all at once.** The hierarchical labels (`n1.0`, `n1.1`, …) are derived from topology on every read by a walk that recursed once per node — and a trunk is a linear chain, one node per committed turn, so at roughly 3,000 turns it overflowed the call stack and every reader of the graph started answering 500 with nothing to repair (labels are derived; there is no file to fix). The walk is an explicit stack now, so depth costs nothing, and the result is cached until the topology actually changes rather than being recomputed on every request.
- **The file editor stops showing a Save as done when nothing was written.** The pane cleared its unsaved-changes marker the instant Save was pressed, before anything could have run — so a Save clicked in the moment between a pane appearing and its service starting (or in a project where that service was never approved) left the buffer looking saved with the file untouched, and said nothing. `service.js` now echoes the control write it actually executed (`ack`), the pane clears the marker on that echo rather than on the click, and a Save with no answer within a couple of seconds says so and names the two things that fix it. A Save the service refuses — a path outside the project root, say — also keeps the buffer marked unsaved now, where it used to go clean beside the error. **You must approve the file editor once more after upgrading:** `service.js` changed, and consent is keyed to its contents, so run `claude-web-chat trust file-editor` the first time a pane sits empty.
- **What you do while the connection is down is no longer thrown away.** Every frame the page sends the daemon — a pane's store write, a pane pinned/locked/minimized/resized, a pane's activity events, a pane script's error — was gated on an open socket and silently dropped when there wasn't one; and because the reconnect's catch-up runs daemon→browser only, the reconcile then replaced the local copy with the daemon's older picture too, so the change was lost at *both* ends with nothing logged anywhere. Those frames now queue in the page (store patches merged into one, one entry per pane, a capped tail for the rest) and are sent once the reconnect's snapshot has been applied, with the local copy re-converged to match. **You may notice** a store value or a pane layout you changed across a laptop sleep now surviving instead of reverting. Typed form values were already covered by the reconnect flush and are unchanged.
- **`node-render`'s description says what the pane does.** It promised "HTML previews of each mount (scripts stripped for safety)" and a store snapshot; it has neither — the pane is an iframe onto the node's live `/preview/node/<id>` document, which splices in the mount runtime and runs every mount's scripts. That description is what Claude reads to decide whether the component fits, so anyone relying on it to embed an untrusted node "safely" was misled. It now names the containment that actually holds (an `allow-scripts` sandbox with no `allow-same-origin`, plus the preview document's CSP) and says plainly that the scripts run. Behaviour is unchanged; the existing directory is refreshed on the next daemon boot, as builtins always are.
- **The first-run tour stops declaring params it never reads.** `step` and `url` were in `web-chat-tour`'s `params_schema` and passed by `claude-web-chat init`; the component reads neither (it advances on observed evidence and never renders the URL).
- **The queue rail reads the parked batch, instead of re-reading the prose meant for Claude.** `GET /api/queue/pending` stripped the structured batch and returned only the wake envelope, so the rail's "Held for next prompt" section reconstructed its rows by matching `- [kind] summary` bullets out of `envelope.content` — text `lib/channel/envelope.js` writes for Claude, with a silent fall back to a bare "N signals awaiting delivery" whenever the shape did not match (a reworded bullet, a summary containing a newline, the 50-line cap on a large batch). The endpoint now returns `items` — the parked batch reduced to the same summary-only fields a queued item shows — and each held row renders through the same row builder a staged one does. **You may notice** held rows now carrying the source and why-wake lines staged rows have always had.
- **Dismissing the update bar remembers the right version.** The × handler recovered the version it was closing by running a regular expression over the bar's own message text. A reworded sentence — or the ✕ landing while the bar was borrowed for one of the other messages it carries, such as "you're up to date" — recorded nothing, so the bar came straight back on the next check in the same session it had just been closed for. The announced version is tracked directly now, and dismissing a borrowed message no longer mutes a release announcement nobody was shown.
- **The ⌘K palette lists the turns the graph draws.** It built its node rows from the raw commit list while every other viewer surface reads the display topology, so a turn that changed nothing — collapsed out of the DAG, the history list and the counts — still had a palette row, and picking it dropped you on a node the graph does not draw: the topbar's ↓ was dead there and only the ↑ fallback got you back out. Reveal the collapsed turns in the graph viewer and they reappear in the palette, as they do everywhere else.
- **A component spawn the daemon refuses now says so on screen.** Clicking a component in the ＋ drawer when the target pane is locked or owned by a service closed the drawer and reported the refusal into the *Manage* tab's status line — a panel that had just been hidden, that does not exist at all on a daemon without the pack routes, and that the next open rebuilds from scratch. The refusal was, in practice, a `console.warn`. It now appears in the same in-page notice the graph viewer uses.
- **`pack list --verify` no longer calls a refused record "locally edited".** A unit whose own provenance record cannot be resolved — an unknown kind, a path that resolves outside its directory — counts as drift, and the list line had one word for every kind of drift, so it blamed the user's edits for something they never touched. It now reads `· record refused`, the same distinction `pack info` and `pack remove` already made.
- **`install` no longer prints two contradictory paragraphs about one file.** A managed file whose baseline was lost while a conflict was outstanding keeps its `.new` sidecar and reports as drift — and both reporting blocks claimed it, so the same file got "merge the sidecar, then delete it" and, immediately below, "differs with no recorded baseline … run `install --force`", which would discard the edits the first was preserving. Only the sidecar reminder is printed for such a file now.
- **`claude-web-chat uninstall` in a directory that is not a project no longer un-registers anything.** It resolved its root tolerantly — falling back to the current directory when no `.web-chat/` was found above — and `remove()` un-registers Claude Code's local-scope entry by running `claude mcp remove web-chat --scope local` *in that directory*. Typing it somewhere random therefore wrote to Claude Code's own config on behalf of a project that never existed. It now reports that there is nothing to uninstall and touches nothing. A directory whose `.web-chat/` was deleted by hand but whose hooks or `.mcp.json` entry survive is still uninstalled — that wiring is what the command exists to undo.
- **A component pack is no longer refused for writing an npm range this build does not parse.** `requires.web-chat` promises that a range shape the small built-in grammar does not implement counts as satisfied — but an x-range (`1.x`, `1.2.*`), a disjunction (`^1 || ^2`) and a hyphen range (`1.2.0 - 2.0.0`) all had a numeric core the clause matcher took confidently and wrongly: `1.x` became an exact pin on `1`, `||` was read as a conjunction nothing can satisfy, and the pack failed validation with `this pack needs web-chat 1, this is 0.7.0`. Those shapes are now treated as unknown, which means satisfied.
- **`update --to <older version>` no longer syncs your project's managed files FORWARD.** Rolling back to a release that predates the registration engine (anything before 0.7.0) fell back to the running build's engine and announced it as "syncing with THIS build's templates, which may be older" — in a rollback they are newer, so the project's rules, skill and hook template were written forward to files the version just activated does not ship. A rollback in that direction now leaves managed files alone and names `claude-web-chat install` — which is the rolled-back build — as the way to sync them with its own templates. An upgrade is unchanged.
- **`install.sh` sweeps the dangling `current.incoming` link an older installer left inside a version directory.** The `mv` that bug fixed deposited the new symlink at `versions/<old>/current.incoming`, and the sweep that came with the fix only cleared `~/.web-chat/current.incoming` — so every install that had ever been upgraded through the broken installer kept the dangling link, and the mtime it stamped on that version directory skewed the prune's newest-first ordering, letting an older version outlive a newer rollback target. Re-running the installer now clears it.
- **`ls --reap` can clear a registry entry that names no project root.** Every surface below the reap is addressed by its root, and a missing root resolves to the current directory — so a hand-edited or legacy entry sent the reap looking for the portfile of the project you were standing in, while the removal of the entry itself threw and was swallowed. `ls` therefore printed the row as `(dead — registry entry is stale)` with a `--reap clears` hint that never cleared it, on every listing, forever. A dead one is now removed by the id the entry carries; a live one is reported and left alone, since nothing can say which surface it describes.
- **Spawning a daemon no longer leaks a file descriptor pair into the process that spawned it.** Both detached spawners opened the child's log file and never closed the parent's copy — and the project-daemon one opened it twice, once for stdout and once for stderr. `spawn()` gives the child its own duplicate, so what the parent kept was pure leak: invisible in a one-shot CLI, but the MCP server is long-lived and respawns a dead daemon on demand, so a Claude Code session leaked descriptors for as long as it ran. Both spawners now go through one `spawnDetached` that opens the log once and closes it as soon as the child owns its own.
- **An interrupted `update` can no longer outrank the release you are running.** The download was staged *inside* `~/.web-chat/versions/`, so a Ctrl-C mid-download (nothing in the CLI handles SIGINT, so the cleanup never ran) left a `wc-release-XXXXXX/` directory that `update --list` printed as a version and the comparator's non-numeric fallback sorted above every real release — so the prune protected the debris and deleted a genuine rollback target instead. Staging moved to `~/.web-chat/staging/`, a sibling on the same filesystem so the move into place is still a rename; only a directory whose name parses as a version is listed, activated or rolled back to; and a staging directory more than a day old is swept by the next download. **You may notice** a `versions/wc-release-…` left by an older build — it is now ignored everywhere, and safe to delete.
- **The pack panel's error text is themed, not hardcoded.** Both `.err` states in the component-pack panel asked for `--wc-coral`, a token no palette block has ever defined, so they painted from the literal `#d05a4a` written beside them as a fallback and no theme could move them. They now use `--wc-comment`, the coral the rest of the chrome already errors in (the push-failure notice, a failed comment reply). **You may notice** those two lines are a slightly warmer coral, and follow your theme.
- **A saved theme reaches the whole chrome now.** Five chrome surfaces — the topbar's gradient and bottom hairline, the dock-button hover, the stepper hover, the queue rail, and the active row in the graph history — were painted from hex literals with a hand-written light-mode twin each: a second palette living outside the `--wc-*` blocks, where no theme could reach it. Setting `--wc-header-bg` still left `#2c2519` at the top of the topbar and a `#211c12` rail. Those surfaces now resolve through tokens — `--wc-topbar-top`, `--wc-topbar-border`, `--wc-rail-bg`, `--wc-hover-bg`, `--wc-row-active-bg`, and `--wc-gold-fg` (the ink on a gold fill, which was the same literal twice) — defined in both palette blocks, so `set_theme` and a saved theme restyle them like everything else. Stock light and stock dark are unchanged pixel for pixel.
- **A graph node the daemon could not read is no longer overwritten by the next commit.** The next node id was seeded only from the node files that *loaded*, so a torn or wrong-shaped `n2.json` — skipped at boot rather than wedging it — left the counter behind it and the next turn wrote straight over the one record of that turn. An id is now claimed by a file existing: the seed scans the `graph/` directory listing, including the `.corrupt-<ts>` copies below, so a skipped id is spent for good and a surviving node whose parent is that id can never graft onto an unrelated new node.
- **An unreadable graph record is kept, not destroyed.** A node file that fails the read, and a torn `graph/_meta.json` before the boot recovery rewrites it, now move to `<name>.corrupt-<timestamp>` beside themselves (newest three kept) — the rule `draft.json` already followed. **You may notice** these files in `.web-chat/graph/` after a crash or a full disk; they are the bytes of a turn the daemon could not parse, and deleting them is safe once you no longer want them.
- **The boot recovery of a torn `_meta.json` can no longer stop the daemon starting.** Recovering `active` from the latest commit ended in an unguarded write, so a `graph/` that had become unwritable (or a directory sitting at `_meta.json`) threw out of the boot path. The heal is best-effort now: the recovered commit point is already in memory, and only persisting it for the next boot can fail.
- **Committed nodes no longer carry the live-only `gen` counter.** `snapshotLive` spread the whole live mount record into every node file and draft while the restore path picked a fixed field list, so the pane re-render counter was written into history nothing would ever read it back from — against the stated decision that committed node bytes were unchanged. A snapshot now carries exactly the fields the restore reads. Existing node files are untouched and load as before.
- **A service child survives a failed store push.** The driver handed to a service-backed component now contains an unawaited call's rejection (one stderr line, the write is lost, the next push carries the state) instead of letting it become an unhandled rejection that kills the child — which, combined with the supervisor's crash-block, silently stopped that service until its next edit. A service that awaits a driver call still sees the rejection.
- **A daemon that dies mid-response no longer hangs the thing that called it.** `lib/client`'s low-level `request()` settled only when a response reached its `end`; a daemon that crashed, was `restart`ed or reset the socket after the headers but before the body completed left the promise pending forever — and because the client deliberately has no default socket timeout (a driver's `/api/wait` long-poll needs none), the MCP tool call, hook or CLI command behind it hung with no error and no timeout. It now rejects with an `ECONNRESET`-coded error, which the client's existing connection-refused handling folds into its respawn-and-retry: a mid-response death behaves like a refused connection.
- **A non-2xx from the daemon is a typed error.** `client.get`/`post` threw a bare `Error` whose only content was a formatted message, so callers could not branch on the status and guessed in both directions. They now throw an `HttpError` carrying `{status, body, method, path}` (the message is unchanged). **You may notice:** `claude-web-chat profile reload` and `claude-web-chat unlock` used to print `✓ reloaded undefined user profile(s)` and `no lock was set` when the daemon answered 404 or 500 — they now report the failure and exit non-zero. The `export` MCP tool returns its documented `{error, ref}` for an unknown node label instead of surfacing a raw transport error to Claude.
- **A reconnect no longer overwrites the node you are previewing, and no longer eats what you typed.** The `hello` frame the daemon sends on every WebSocket connection — first open, and equally the reconnect after a laptop sleep, a `claude-web-chat restart` or a self-update — was applied by its own hand-written code path, separate from the one `reset` uses. It ignored the detached-preview state, so a reconnect while viewing an older node re-mounted the live surface straight over it; it removed nothing, so a pane the daemon had cleared during the drop lived on locally until the next full reset; and it re-mounted every pane blindly, destroying values you had typed in the meantime. All full-surface snapshots now go through one applier (`applySnapshot` in `public/app/mounts.js`) that owns the preview fold, removes panes the frame does not carry, and keeps the live DOM of a pane whose content is unchanged. **You may notice:** after a reconnect, form values typed while the connection was down are preserved and pushed to the daemon (they used to be marked as sent before the send was gated, and were silently lost), and a pane that is unchanged is no longer torn down and rebuilt — its script keeps running, and the store keys that moved are published to it instead. A `hello` is now authoritative about the store as well: a key the daemon does not have is published as removed rather than kept locally.
- **A mount id can no longer name the graph inspector's chrome or the export shell's.** The reserved-id set had a derived half (the ids in `public/index.html`) and a hand-maintained half for the ids the shell builds lazily — and the hand half had fallen four behind: a pane mounted as `gv-preview`, `gv-diff`, `gv-diff-sect` or `gv-set-active` claimed the id the graph inspector later looks up, so the node preview drew into the pane and the inspector's Set-active button stopped working. Both halves are derived now — a test scans `public/app/*.js` for the id literals the shell writes — and the same derivation covers the two documents that write a pane host with no free-id check of their own, the export shell (`export-head`, `export-main`, `export-empty`, `wc-export-data`) and the glance preview. Only the two ids a helper builds from a computed name (`wc-theme-global-css`, `wc-theme-node-css`) stay hand-listed. Renaming a mount that used one of these ids is the only user-visible effect; nothing else changes.
- **Two panes of one component with different params are two trust notices again.** The `service:trust` / `service:trust:clear` frames carried the `service.js` hash alone while consent is keyed to (root, hash, params), so two variants of one service collapsed into a single card in every connected browser — and clearing either pane, or approving just one variant, took the other's card away while its request was still pending on the server (the CLI still listed it). Every notice now carries the trust key the daemon minted, plus the params it is about, and the browser keys its cards and dismissals by that key.

- The release tarball is now byte-reproducible across operating systems. `scripts/build-release.js` left the gzip header's OS field as zlib stamped it (3 on Linux, 19 on macOS), so rebuilding a tagged tree on a different OS than the one CI cut it on produced a different sha256 — a verifier's only reading of that is tampering. The byte is now pinned to 255 ("unknown", per RFC 1952). Already-published artifacts keep their published checksums; this affects builds cut from here on.

### Internal

- **One CRC-32 and one ZIP writer.** The browser-extension download served a store-only ZIP encoder written inline in `lib/server/routes/extensions.js`, with its own bitwise CRC-32 next to it, while `extensions/make-icons.js` carried a second, table-driven CRC-32 for PNG chunks — a checksum Node has shipped natively since 22.2. Both now come from `lib/core/zip.js` (`writeZipStore` / `crc32`), which prefers `zlib.crc32` and keeps one fallback table for the point releases below it, guards the 32-bit header fields instead of silently writing a wrapped value, and walks the tree in sorted order so a directory packs to the same bytes every time. The encoder finally has a round-trip test — including a real `unzip -t` where the platform has one — and two ratchet rows keep either copy from growing back. The archive a user downloads is unchanged apart from entry order, and the checked-in icon PNGs are byte-identical.
- **The shell's stylesheet no longer describes chrome that does not exist.** Four families of class rules matched nothing in the product — `.qchip` and its `@keyframes qpulse` (the queue rail's collapsed chips, renamed `.rail-chip` long ago), `.rchip` (graph history row chips), `.pin-menu-text`, `.spacer` — alongside a `.update-banner.ok` success state and a `.ub-btn:disabled` for the one-click "Update & restart" flow that was removed, and six per-component `.hidden` rules shadowing a global `.hidden` that is already `!important`. Two comments described surfaces that had since shipped or been deleted. All gone, and `test/shell-chrome.test.js` now fails the build for any class `public/app.css` styles that nothing in `public/`, `templates/`, `lib/` or `extensions/` can set, with a named allowlist for the four class names `queue.js` composes at runtime.
- **One palette in `public/app.css`, ratcheted.** The 42 never-firing `var(--wc-x, #hex)` fallbacks are gone — the sheet is loaded by `public/index.html` alone, where `:root` defines every token asked for, so each fallback was a second (and in places a different) value for a colour that always had one. ## [0.7.0] - 2026-08-28

### Upgrading from 0.6.0

No state migration runs — the on-disk schema is unchanged, so your graph, drafts, components, themes and packs are read as-is. What you have to do:

1. **Upgrade Node first — 22 is a hard floor.** A transitive dependency is ESM-only, so on Node 18–21 the daemon does not start at all.
2. **After `claude-web-chat update`, run `claude-web-chat install` once in each project.** This hop is performed by the 0.6.0 binary, which syncs managed files against *its own* templates — so the new `.claude/rules/web-chat.md`, the capture-profile skill and the `.gitignore`/`.mcp.json` reconcile arrive only on that next install. `status` says `N need refresh` until you do. (From 0.7.0 forward, `update` syncs with the new build's engine.)
3. **Re-trust the two builtin services.** Consent is keyed to the contents of `service.js` and both builtins changed: run `claude-web-chat trust git-dashboard` and `claude-web-chat trust file-editor` the first time such a pane comes up empty (bare `claude-web-chat trust` lists what is waiting).
4. **Finish a managed-file conflict by merging the `.new` sidecar and then deleting it.** Deleting it is the resolution; nothing deletes it for you, and `install`, `update`, `status` and `init` keep naming it until it is gone. Do not `git clean` an unmerged sidecar away — the offer is recorded as made, so you would silently keep the older text. `install --force` remains the alternative that adopts the shipped file and discards your edits.
5. **Reach the surface as `localhost` or `127.0.0.1`.** The daemon and the capture hub now check the `Host` header and answer `421 Misdirected Request` to anything else, so a forwarded or tunnelled port, a container hostname or a proxy that rewrites `Host` is refused — for the page as well as the API. Set `WEB_CHAT_HOST` to the address you bind (accepted alongside loopback), or to a wildcard such as `0.0.0.0`, which skips the check and leaves the bind address as your only access control.
6. **`claude-web-chat install` typed in a subdirectory now installs into the enclosing project root.** A deliberately nested second surface inside another installed project is no longer supported. `uninstall`, `on`, `off`, `status` and `doctor` resolve the same way.
7. **`init --json` renames `surfaces[].live` to `surfaces[].pid_alive`** (and adds `reachable`). Anything parsing that report needs updating.
8. **`file-editor` fences paths by realpath now**, so a symlink inside the project that resolves outside it — including one whose target does not exist yet — is refused where it used to be followed. Use `unfenced: true`, or point `root` at the tree you mean.

Three more repairs are conditional — they apply only if they describe you, and each is spelled out in *Fixed*: a committed `${CLAUDE_PLUGIN_ROOT}` stub in `.mcp.json` that the 0.6.0 code rewrites to an absolute path one last time (check `git diff .mcp.json`); an install made by an `install.sh` older than this one, whose `current` symlink may still point at the previous version (check `claude-web-chat version`); and a component ever saved over a builtin name, whose shadowing directory the daemon now names on stderr at boot for you to delete by hand.

### Security

- **Graph-node previews carry a Content-Security-Policy.** `/preview/node` is served from the daemon's own origin and the graph viewer instantiates one per node thumbnail plus the glance card, so pane scripts from nodes you are not on were re-executing unattended with `fetch` reach into `/api/*`. **You may notice:** inside a *preview*, a pane that pulls an image, font or iframe off the network renders empty; the live surface is unchanged.
- **`/api/embed-check` can no longer be used to probe your local network.** The route has the *daemon* fetch a caller-supplied URL and nothing restricted the target; loopback, private, CGNAT, link-local and reserved addresses — and any name that resolves to one — are refused at DNS time, every redirect hop is re-checked, and credentials are stripped. **You may notice:** nothing in the `website` pane. A `localhost` URL is framed without asking the daemon at all, and for every other target the daemon labels this one refusal (`code:"private-target"`), which the pane answers by framing the URL itself — so a dev server on `192.168.x`, `myapp.test`, `foo.local`, `host.docker.internal` or a Tailscale address still loads, because the browser is under no such restriction (see *Fixed*, below). What changed is that the daemon will not dial any of them on a caller's behalf.
- **`GET /api/export/:ref?format=file` refuses browser-originated requests.** The disk-writing half of the export route had no gate, and as a plain GET an `<img src>` on any page could write files under `.web-chat/exports/` and spam the event ring. The `export` tool, `claude-web-chat export` and the topbar **⬇** button are unaffected.
- **The daemon and the capture hub check the `Host` header.** A rebound DNS name reaches a loopback-bound daemon *same-origin*, so no `Origin` is sent, CORS reflected `*`, and the WebSocket gate was never consulted. The check is mounted first on both apps and folded into the WS upgrade; refusals are `421` naming the host dialled, and the hub's protocol version is bumped so the next instance boot bounces a pre-gate hub. See upgrade step 5.
- **A graph node's name can no longer run script in the chrome.** The ⌘K palette interpolated the node label into an `innerHTML` template while the bookmark route only trims it, so a bookmark named `<img src=x onerror=…>` executed in the surface's privileged origin.
- **`javascript:` hrefs no longer reach a capture pane or the reader sidecar.** The URL helper passed the scheme through, three bundled profiles carried ungated copies, and the one regex gate was bypassable with an embedded tab. `safeHref` now normalises through `new URL` and returns `''` for anything outside http/https/mailto/tel, keeping the link text.
- **Both builtin services are hardened.** `git-dashboard` passed store values into git's argv, where a leading `-` is an option and `git log --output=<file>` writes files — so anything on the surface could make the daemon overwrite a file you can write. `file-editor` joined a version id into a path unchecked, fenced lexically (a symlink out of the project was followed), and re-executed the persisted `editor_ctl` write on every respawn, silently rewriting a file from a stale buffer. Refs are now checked against what the service itself read and fenced behind `--end-of-options`, the fence is realpath-based, and the control cursor starts at the service's start time, so only a write stamped during this service's life executes and a respawn adopts view state (`open`/`browse`) only. **You may notice:** an `editor_ctl` write whose `seq` is not a wall-clock timestamp is ignored, and both services ask for trust again (upgrade steps 3 and 8).
- **A pack archive can no longer OOM the daemon by decompressing.** The pre-extraction gate gunzipped the whole archive into one Buffer with no ceiling, which the 64 MB download cap does not bound. Inflation, and so extraction, is capped at 256 MB.
- **A component name is validated before it becomes a path.** Express decodes `%2f` into a route parameter, so `..%2f..%2fx` reached the component read, seed and `use` routes unguarded — and `use` writes the name into the string the service supervisor forks. A name that fails the kebab grammar answers 404, and `pack remove` re-checks recorded unit names the same way.

### Added

- **A stated platform position — `docs/platform-support.md`.** macOS and Linux are supported (CI runs the full suite on both, Node 22 and 24); Windows means WSL2. It lists the known cross-platform defects rather than filing them away, with per-platform findings on the `platform/linux` and `platform/windows` branches.
- **A mount id may not name the shell's own chrome.** `main`, `topbar`, `status`, `dock`, `stage`, `overlay`, `drawer`, `minbar`, `queue-rail`, `cmd-palette` and the rest are refused on `render`, `use_component` and the capture path with `{ok:false, reserved:true, hint}` — a 200 with `ok:false`, because the tools and the drawer read `.ok`. The static half of the set is derived from `public/index.html` in a test, so it cannot fall behind the chrome.
- **A pack install is one transaction, and re-installing a pack is a real update.** An undo journal copies overwritten files aside and unwinds on any throw, so a failed install leaves the tree byte-identical and a failed update restores the previous version; the record is written first as a `pending` marker in its own file, so a half-install is never reported as installed (`pack list` shows it under **interrupted installs**, and re-running the install is the whole recovery). `pack install <same url>` now also diffs the previous record against the new plan. **You will notice:** an update can delete files, which it never did before — except ones you have edited, which are kept and released to you.

### Changed

- **Turns that changed nothing are hidden in the graph viewer.** Graphs written before fold-forward kept a run of byte-identical nodes, one per chat-only turn, which is what makes a long graph unnavigable. The payload now reports which nodes match their parent and which node absorbed each run. Nothing on disk changes, labels such as `n1.7` still name the same node, a filter chip shows them all again, and a node is never hidden if it is a root, fork, tip, active, bookmarked or named.
- **A capture pane is a pane like every other one.** It emits the ring `render` event (so it shows in `get_events` and the service supervisor sees it), carries a `gen`, is soft-rejected over a user-locked pane, and **carries the pane's `form_state`** — so a value you typed into a capture pane survives the next capture of that page. The extension still takes over its own pane on every capture; that one is deliberate.
- **`ls --reap` asks instead of signalling, and never signals a pid it cannot identify.** A row is stopped only when a daemon answers on its port and reports the pid the registry named, through the same acknowledged-shutdown engine `stop` uses — so a reaped surface's uncommitted work is saved to `draft.json`. **You will notice:** a wedged daemon (pid alive, port silent) is printed with its pid and a `kill` hint instead of being stopped, because from the outside it is indistinguishable from a stranger's process that inherited the pid.
- **`ls`, `init` and `init --json` tell the truth about a stale surface.** `surfaces[].live` becomes **`surfaces[].pid_alive`**, joined by `reachable`; the old field was permanently true, because the read pruned dead entries before anything looked at them.
- **One HTML escaper, and capture profiles get a helper kit instead of rolling their own.** `escapeHtml` lives in `lib/core/html.js` and escapes five characters (`& < > " '`) everywhere; extractors and panes receive `{ esc, collapse, safeHref, absolutize }` on their context, since a profile bundle lives outside the package and cannot `require` into it. **Byte-level consequence:** where a copy escaped only four characters, an apostrophe now serialises as `&#39;`. It renders identically, but the bytes change in the reader-lite pane, in the `<id>.simplified.html` sidecar, and in the HTML fields of the **wikipedia** and **reddit** distillates `get_captures` returns (`summaryHtml`, `valueHtml`, `bodyHtml`, `textHtml`). The `article` distillate was already on the five-character escaper and is unchanged; the youtube distillate carries no HTML fields.
- **An invalid `profile.json` is a logged skip rather than an inert profile.** A typo'd matcher `type`, an uncompilable regex or a malformed `pane` block used to load cleanly and simply never match; such a bundle now disappears from `list_profiles` and the extension's capture button, with the reason on the daemon log. In the other direction, a bundle with no `name` is accepted and takes its directory name.
- **Unresolvable relative hrefs and `data:` URLs disappear from distillates and reader panes.** `safeHref` returns `''` where the old resolver returned the raw value; the link text is kept. In practice: pages captured with no URL, and inline `data:` images in the reader view.
- **`article` and `simplify` resolve links against the page URL, not its origin.** `<a href="c.html">` on `https://x.com/a/b/page.html` used to resolve to `https://x.com/c.html` — broken images and dead links on any site using relative paths.
- **One wording for a managed-file conflict, and it terminates.** The reconcile recorded nothing when it offered a `<file>.new`, so a hand merge matched neither the baseline nor the shipped bytes and the same conflict re-fired on every install and update forever. The conflict branch now records the bytes it offered — `managed.json` means "the shipped bytes this file was last reconciled against, applied **or** offered" — so a merge settles as *kept (locally edited)* while a genuine template change still announces itself. The `.new` sidecar is the reminder and persists until you delete it; it used to be destroyed silently by the next reconcile, taking the merge material with it. No migration; how you finish one is upgrade step 4.
- **`claude-web-chat update` syncs the whole registration, and never writes Claude Code's own config.** The managed-file sync now runs the newly installed build's engine out of `versions/<target>` — it used to be bound at module load from the tree being replaced, so it compared your project against the *old* templates and reported everything up to date — and it also runs the registration engine's `apply()`, adding a missing `.web-chat/` line to `.gitignore` and reconciling the `.mcp.json` entry. What it will not do is `claude mcp add web-chat --scope local`, which writes Claude Code's config outside the project; `update` prints that command instead. **This fix does not apply to the 0.6.0 → 0.7.0 upgrade itself**, which the 0.6.0 binary performs with its own templates: see upgrade step 2.
- **Node 22 is now the floor** (`engines: >=22`, was `>=18`). `entities@5`, reached through `node-html-parser@8`, is ESM-only, and `require(esm)` landed in Node 22 — below that the daemon throws while `lib/server` is still being required. Node 18 and 20 are past end-of-life; CI covers 22 and 24.
- **Every URL the CLI prints honours `WEB_CHAT_REPO`.** The slug was hardcoded in four user-facing strings, so pointing web-chat at a fork moved the downloads while `update`, `version` and `init` still told you to `curl` the original repository's `install.sh`.
- **A `clear` naming an id that is not mounted no longer emits a clear frame.** The response is still `{ok:true}`; the wire now describes what the server actually did.

### Fixed

#### Daemon lifecycle

- **`stop` no longer reports a stopped server as running, or tells you to `kill -9` a pid that is gone.** A dead pid's leftover portfile and registry entry are reaped and the outcome reported as `{ok:true}`, so `restart` proceeds instead of aborting.
- **A daemon asked to stop always releases its records.** The SIGTERM `stop` fires at the end of its budget used to truncate a working shutdown instead of escalating a stuck one, leaving a stale portfile behind.
- **One unresponsive browser tab can no longer hold a shutdown open forever.** The connection drain gets a one-second grace and then hangs up, so a merely slow browser gets a hard hangup rather than a clean close code — and `stop`'s budget is now sized on a bounded worst case.
- **A departing daemon can no longer tear down the live one's records.** The `~/.web-chat` registry entry is now released under the portfile's ownership rule; an orphan's exit used to delete the live daemon's entry, taking `ls`, `doctor`'s registry check and the capture hub's routing with it.
- **`ensureHub` no longer stalls in silence when the hub belongs to another user.** An `EPERM` on the bounce ends the attempt immediately, naming `WEB_CHAT_HUB_PORT`, instead of costing two full waits and returning a `null` nobody logged.

#### Install & registration

- **`install` in a subdirectory installs into the project** instead of creating a nested surface Claude Code never loads. See upgrade step 6.
- **`uninstall` is reversible again.** It now also runs `claude mcp remove … --scope local` (printing the command when `claude` is not on PATH), so a "clean" removal is not undone by the first tool call re-creating `.web-chat/`.
- **`doctor` and `status` no longer pass a project that is missing half its hooks.** They report per event against the template; a project that had lost its `Stop` hook used to look healthy while no turn ever committed. The output shape changed with it: `status` now prints Hooks as `N/M registered` naming any missing event, and can report the MCP entry as `— NOT resolvable: <reason>` — worth knowing if you parse it.
- **`doctor`'s MCP repair points at `~/.web-chat/current/`,** not at a `versions/<v>/` path that pruning deletes three updates later — which silently stopped the MCP server from spawning, inside a local-scope registration that never self-heals.
- **`install` stops rewriting a committed `${CLAUDE_PLUGIN_ROOT}` stub to your machine's absolute path.** **On this upgrade only**, the 0.6.0 code performing it rewrites the placeholder one last time — check `git diff .mcp.json`, restore the stub, re-run `install`.
- **Re-running `install.sh` upgraded nothing.** The `current` symlink swap put the new link *inside* the old version directory, so every curl-one-liner upgrade after the first printed the new version and left all three commands on the old code (`claude-web-chat update` was never affected). **If you have upgraded that way, check `claude-web-chat version`** — re-running the new installer repairs the link.
- **`on` in a project that was never installed refuses and names `claude-web-chat init`,** instead of printing the reassuring "web-chat is not disabled for this project" and changing nothing.
- **An MCP tool call in an uninstalled project names a command that would help.** The disabled envelope carries `reason: 'not-installed' | 'marker'`, and the hint says `init` for the first.
- **`install` no longer kills `init` mid-sequence** by calling `process.exit(1)` from inside a library call on a malformed `.claude/settings.json` or `.mcp.json`.
- **`init` refuses Node 18–21** instead of passing them with a green tick and failing obscurely at `open` seconds later.
- **`claude-web-chat open` prints its manual-open fallback when there is no browser launcher,** rather than dying with a raw stack — a missing executable arrives as an async `'error'` event, so the `try`/`catch` around `spawn` was dead code.

#### Surface & graph

- **A pane could delete or hijack the surface's own chrome by naming it** — `render({id:'main'})` removed `<main>`, `id:'overlay'` the graph viewer, and the removal replayed on every reload, so the surface stayed dead until the mount was cleared from outside the browser. The client now only removes mount hosts and resolves targets against real slots. (The server-side refusal is in *Added*.)
- **The surface no longer comes up dead in a private window or with site data blocked.** `localStorage` *throws* under those conditions, and the unguarded read was the first statement the app ran, so the whole module graph went down with it.
- **One bad pane no longer reads as a dead surface.** Mounts from the `hello` frame are isolated, so one throw no longer takes the active pill, the queue rail and the version check with it.
- **Keyboard navigation, fork glyphs and the inspector breadcrumb follow the graph the viewer draws.** ArrowDown used to select a *hidden* node (no glyph, no camera move, a second press needed), a trunk node was labelled `⑃ FORK`, and the fork count read one high; `[`/`]` and the topbar's ↑/↓ now step where the arrow keys do.
- **Holding an arrow key can no longer leave the inspector describing one node while its buttons act on another.**
- **`Set active` from the graph overlay honours a queued re-aim.** The inspector button and the glance card's ◉ used to drop out of preview even when the server only *queued* the move, leaving an old node on screen and treated as live.
- **No native dialogs left in the chrome.** The three `Set active` failure paths used `alert()`, which wedges an automated driver.
- **The comment popover is dismissed by the same layer as every other panel,** so Escape reaches an open thread and opening another panel closes it.
- **`use_component` no longer clobbers a pane it does not own, and stops dropping the pane's theme.** It takes `render`'s mount-set path now and accepts `force`; the missing `gen` also let a queued Revert delete the fresh pane.
- **`use_component`'s schema gained `force` and `signals`, which its description already promised** — a top-level `signals` array used to be silently discarded, so the declared wake never registered.
- **A render that supplies a `theme` for an existing pane applies it,** rather than keeping whatever theme the pane was first created with.

#### State durability

- **A torn `graph/_meta.json` no longer boots you to a blank surface and then deletes your draft.** All three graph records are written atomically now, and an unreadable one recovers the active node from your latest commit instead of looking like a deliberate wipe.
- **A graph node file containing `null` or `{}` no longer wedges a project's daemon forever.** Both are valid JSON, so the old skip-on-error guard (which wrapped only the parse) let them through to throw later; the shape is checked inside the read now.
- **A draft the daemon cannot use is kept, not deleted** — renamed aside as `draft.json.corrupt-<ts>`, newest three kept. It is still not applied, but the bytes are recoverable.
- **An unreadable `_version.json` no longer skips every pending migration.** A missing file, a truncated one and an `EACCES` all returned `0`, which the runner reads as "fresh project — stamp and run nothing"; an unusable file now warns and is assumed to be v1.

#### Capture, packs & services

- **HTML entities are decoded once, everywhere.** Inline walkers read the raw source text, so `Tom &amp; Jerry&#8217;s&nbsp;show` reached the `article` distillate undecoded and the reader pane double-escaped it.
- **A nested list no longer emits its items twice** (`querySelectorAll('li')` descends into nested lists, so the inner item appeared merged into its parent and again on its own).
- **`inspect_capture { profile }` re-runs the profile with the capture's URL.** It had no `url` parameter, so the authoring dry-run its description advertises ran every extractor with an empty URL.
- **A `mount_suffix` collision now actually resolves** by walking to a free suffix, instead of falling back to the name that collided.
- **Re-using a service pane's id with different params restarts — and re-gates — the child.** Identity is now the (`service.js`, params) pair, matching the trust key; `file-editor`'s `unfenced:true` is exactly what params can change about what you approved.
- **A service that never finished shutting down could not be killed.** A second signal is decisive now — the child used to answer both the IPC `stop` and the follow-up `SIGTERM` with a handler that returned immediately, and there is no `SIGKILL` above it.
- **A restarted service pane could leave a second copy of the service running,** because a reconcile respawns in one pass and the old child's exit was read as the replacement crashing — dropping the live child from tracking so nothing ever stopped it.
- **A pack change reconciles the service supervisor,** so an update that removes a component's `service.js` stops the approved child with it.
- **A quarantined pack belongs to the project it was staged in.** Records keyed on the pack name alone let a second project orphan the first project's staged tree, read its files through `review`, and install and delete them through `approve`.
- **`pack remove` unlinked whatever the installed record named, with no containment check** — and `packs.json` is project-tier, so a cloned repo could ship a record whose unit name is `../../../..`. Records are validated at read time (kebab unit names, path refusals, realpath containment anchored on the project root); a failing unit is refused whole and kept so the evidence survives, and `--force` does not override it.
- **`planInstall` was documented as pure and created six directories** — including for the plan computed over a tree you have *not* approved.
- **`save_component` over a builtin name permanently broke that builtin,** writing a component with no `builtin` marker — the one thing `seedBuiltins` repairs on — so every later fix to `git-dashboard` or `file-editor` silently failed to land. **Two consequences:** the refusal is prospective, so a project where this already happened keeps the shadowed component and cannot overwrite it back; the daemon names the directory on stderr at every boot with the path to delete, and removes nothing itself, because your edits are in it. And a component directory whose name is not plain kebab-case stops resolving through the read routes rather than resolving by luck.
- **The `website` component reaches local dev servers again.** This release's SSRF fence on `/api/embed-check` made the pane skip its pre-check using a hand-copied, narrower private-address list, so a target that list missed — `myapp.test`, `foo.local`, `host.docker.internal`, a Tailscale `100.x` address, any name only your resolver can place — was pre-checked, refused by the daemon and painted "could not reach this URL" although the browser could frame it perfectly well. The daemon now labels that one refusal (`code:"private-target"`), the pane frames the URL itself when it sees it, and the private-address list exists in exactly one place. The daemon still never dials a private address on a pane's behalf.

### Internal

- **One mount-set engine — `lib/server/domain/mounts.js`.** Four routes hand-copied the reserved-id / lock / owner / `gen` / carry-rules / emit sequence and each dropped a different part of it.
- **One project-registration engine — `lib/setup/registration.js`,** consumed by `doctor`, `status`, `install`, `uninstall`, `on`, `off`, `update` and the MCP dispatcher — replacing five answers to "which root", two hook counts that counted different things, and two contradictory `${CLAUDE_PLUGIN_ROOT}` policies.
- **One durable-JSON-record engine — `lib/core/fsjson.js`:** an atomic write plus a four-state read (`ok`/`absent`/`corrupt`/`invalid`), replacing two spellings of the temp-file idiom and five private readers that each collapsed a different pair of states.
- **The capture route is thin.** `lib/capture/pane.js` owns pane rendering (so `profile dry-run` shows what the surface shows), and one bundle loader is shared by the daemon and `profile validate`.
- **Four generic helpers moved down into `lib/core`** with re-exports at their old homes: realpath containment (the pack pipeline's security walk was importing the *updater* for it), `escapeHtml`, the Node floor and the repo slug. `--wc-*` token sanitising also has one home now, replacing three different strip sets — a newline inside a token value becomes a space.
- **`topbar.leavePreview(opts)` and `graphIndex()` in the chrome.** The exit-preview transition had eight drifting copies of the flag that gates every write out of the page; the display-topology index was verbatim twice and decides both the fork glyphs and what the keyboard expands.
- **The test harness gained an engine, and `npm test` a timeout and a HOME sandbox.** Nine files carried a private deadline poll under four names with three incompatible contracts, and three opened SSE streams that could never reject. `--test-timeout=60000` turns an unsettled await into a named failing test (deliberately not `--test-force-exit`), and an `--import` sandbox points `HOME` at a throwaway dir before any `require`, so the suite no longer writes your real `~/.web-chat` or bounces your live capture hub.
- **Four ratchets, and coverage where there was none.** A dependency-direction test fails any relative `require()` edge the documented layering forbids; a doc-truth test checks every machine-checkable claim in the shipped docs (tools, routes, commands, the engines table, no hardcoded `localhost:5173`); `process.kill(` and browser storage joined the conventions tripwire. First tests arrived for `ls` and `--reap`, for keyboard navigation and the exit-preview divergences, and for the comment-pin composer.
- **The docs stopped claiming things the code stopped doing.** CLAUDE.md's route `ctx`, the `tab-stream` README's deleted `wait_for` and its 5 MB body limit (it is 200 MB), `embed-helper`'s hardcoded port, `docs/export-pages.md` (a pre-implementation plan linked as the user doc), and four sections of `docs/capture-profiles-and-panes.md` specifying an interaction slice that does not exist — now correct, or banner-marked `NOT BUILT — design`.
- **The MCP server stopped nudging about an unmerged `.new` sidecar.** Its once-per-session drift line says "run `claude-web-chat install`", and `install` cannot merge a conflict for you — the resolution is by hand — so a `pending` row would have repeated an unactionable reminder every session until the user got to it. `status`, `init`, `install` and `update`, which the user asks for, all still report it.
- **The daemon says so at boot when no capture hub could be brought up.** `ensureHub()`'s return value was discarded, so a hub that could not start (another user's, on the machine-wide hub port) was silent everywhere but `doctor` while captures from the browser extension had nowhere to land. It now writes one stderr line naming `claude-web-chat doctor`.

## [0.6.0] - 2026-08-24

### Security
- **`Authorization` is now dropped on a cross-host redirect.** A GitHub release asset URL redirects to object storage on a different host, and the redirect follower carried every header across that hop. Latent while nothing minted a token — but `GITHUB_TOKEN` has to be honoured (unauthenticated `api.github.com` is 60 requests/hour/IP, and a pack install makes several), which would have turned it into a live credential handed to whoever answered at the far end. A token is also only ever minted for a `github.com` host now, never for a URL the user pasted.
- **The daemon and the capture hub now bind loopback.** Both called `listen(port)` with no host, so everything web-chat serves — the graph, the shared store (which holds whatever a `file-editor` pane has open), arbitrary HTML/JS injection through `POST /api/render`, and `POST /api/update` — was reachable from the local network with no authentication. Set `WEB_CHAT_HOST` to opt into a different interface deliberately.
- **The WebSocket endpoint now checks `Origin`.** Browsers apply no same-origin policy to WebSocket connects and the `hello` frame is an unconditional full-state disclosure, so any page a user visited could open `ws://localhost:<port>/ws`, read the entire store and every pane's HTML, and write store keys back. Non-browser clients (local drivers, the CLI) send no `Origin` and are unaffected.
- **Service consent records moved to the user tier** (`~/.web-chat/services/trusted.json`). They used to live at `.web-chat/services/trusted.json` *inside the project*, so a repository could ship its own pre-approval: cloning a hostile repo and opening it ran its `service.js` with no prompt.
- **Service consent moved to the terminal — `claude-web-chat trust`.** It used to be a decision made on the surface, which cannot work: pane scripts are compiled with `new Function` and run in the page's own window realm with `document`, `fetch` and `WebSocket`, and no CSP is served, so a component's pane can synthesise a click on any button, open its own same-origin socket and read anything broadcast to the shell, and call any localhost endpoint. Nothing delivered to that page is a secret from the code the gate exists to gate. The surface now shows a notice naming the command; only a shell can grant. Consent is also keyed per **(project root, `service.js` hash, params shape)**, so the same component in another project, an edited service, or different params each ask again — which is what stops one `file-editor` approval covering `unfenced: true`, or a cloned repo inheriting a grant.
- **Capture reads are no longer world-readable.** The CORS layer reflected whatever `Origin` arrived, so any website the user visited could read every capture — distilled content and raw DOM — from the unauthenticated `GET /api/captures*` routes. Only extension and same-machine origins are reflected now.

### Fixed
- **The surface's first paint died on Node 18 and 20.** `public/app/mounts.js` read `navigator.platform` unguarded to pick `⌘` vs `Ctrl` for the zero-state's keyboard hints, and `globalThis.navigator` only exists from Node 21 — so on the versions `package.json` actually claims to support, the `ReferenceError` escaped the `hello` WebSocket handler and took the whole initial render with it. Found by CI's first-ever run: the suite had only ever run on a maintainer's Mac, on a newer Node than any supported floor.
- **The `＋` button never closed the drawer.** Every other chrome trigger declares `aria-controls`, which is what opts it into the dismiss layer's skip-the-panel-I-own rule; `＋` declared none, so `pointerdown` closed the drawer and the button's own click immediately reopened it. It also expressed openness with `.open` while every other panel uses `.hidden`, which is why the dismiss layer carried two special cases for it.
- **A component saved mid-session was invisible in the ⌘K palette until a reload.** The palette memoised its own component list and nothing ever invalidated it. There is now one cache, invalidated by a `components` frame the daemon emits wherever the component set can move — so a `save_component`, or a whole pack install, shows up everywhere at once.
- **A component whose `meta.json` name disagreed with its directory was listed but unspawnable.** The registry listed by `meta.json`'s `name` and resolved by directory, so such a component appeared in the drawer and the palette under a name `use_component` could not resolve. The directory name is the identity now; the disagreement is shown as a chip instead of silently preferred.
- **A soft rejection from `use_component` looked exactly like success.** The drawer discarded the response, so spawning into a locked or driver-owned pane simply appeared to do nothing.
- **Service-backed components could never be approved at all.** The trust prompt was emitted as a render targeting `overlay`, which the client resolves to the graph-viewer element — `display:none` until the user presses `G`. The prompt was filed inside a hidden panel, so both shipped builtins (`git-dashboard`, `file-editor`) and every user-authored service simply never started, with no prompt and no error. Approval is now a terminal command (see Security above), and the surface's notice is re-announced to every arriving viewer so a refresh mid-prompt no longer leaves a pane sitting there unexplained.
- **`claude-web-chat docs` crashed on every installed copy.** `docs/` was missing from the package `files` allowlist, so the three pointers the shipped rules file gives Claude all died with a raw `ENOENT` stack. The directory now ships, and a future packaging slip degrades to a message instead of a crash.
- **A single truncated node file could wedge a project's daemon permanently.** `graph.load()` parsed every node through a bare `JSON.parse`, so one partial write — a crash or a full disk — threw out of the unguarded `createServer` call path and the daemon could never boot again for that project. Unreadable nodes are now skipped with a warning.
- **Re-running `install` started a second daemon on the same project** and overwrote the portfile, orphaning the first — which kept running and kept writing the same graph directory, invisible to `stop`, `status` and `doctor`. It now probes for a live instance first, matching every other spawn site.
- **A Push could report "Delivered to Claude ✓" and be silently dropped.** Two causes, both fixed: `install` pinned `WEB_CHAT_CHANNEL=1` into `.mcp.json`, which made the MCP server start a channel bridge in *every* session including ones launched without the capability flag; and the bridge's ack confirmed only that bytes were written to stdout, not that anything received them. The env now comes solely from the launch line that also carries the flag, `install`/`update`/`doctor` clean a stale one, and an ack with no live consumer leaves the batch retained so the parked-delivery backstop still fires.
- **The launch command web-chat printed could not work.** `LAUNCH_COMMAND` omitted the `server:web-chat` argument the flag requires, so the incantation shown by `install`, the queue rail and `doctor` was inert.
- **`list_components` returned cross-tier duplicates.** The registry deduped on `get` but not on `list`, so a name present in both tiers appeared twice, identically, with no signal which one `use_component` would resolve to. Shadowed tiers are now reported on the surviving entry instead.
- **`get_graph` now reports `pending_bookmark` and `pending_reaim`** — the name of a graph the user just started (applied to the next commit) and a navigation queued during the current turn. Both were previously invisible, so Claude could be working inside a graph the user had named without any way to know it.
- Documentation no longer hardcodes `http://localhost:5173`. The port is per-project and walks upward, so that URL was wrong for every project after the first — and the rules file shipped into user projects was telling Claude to send people to another project's surface.

- **The port walk now probes before binding, and web-chat's own clients dial `127.0.0.1` rather than `localhost`.** Both fell out of the loopback bind above: a bind to `127.0.0.1:P` does not collide with a process holding the wildcard `*:P`, so the walk began handing out ports that already had a server on them — and because every internal client resolved the *name* `localhost`, which is both `::1` and `127.0.0.1` on a dual-stack machine, requests could land on whichever daemon that resolution happened to pick. Observed in practice while upgrading: a new loopback-bound daemon took a port a legacy wildcard-bound one still held, and another project's queue started arriving.

### Added
- **Component packs — `claude-web-chat pack`, and the `＋` drawer's Manage tab.** A pack is a git repository that installs as components **plus a Claude skill**, and the skill is the whole point: `list_components` is a *pull* (Claude only learns a component exists if it decides to call the tool) while a skill's frontmatter description sits in context from session start. The format was specified and had no code behind it; this is the pipeline.

  Fetching prefers a published release carrying `SHA256SUMS` (verified before anything is unpacked) and otherwise falls back to the repository tarball **pinned to a resolved commit sha** — an asset can be deleted and re-uploaded under the same tag, a commit sha cannot, so the weaker-looking option is the stronger pin. `pack get` downloads for review without installing: the verified tree is staged where nothing in web-chat reads it, inert *by location* rather than by a flag someone has to check, and `pack review` shows the manifest, the install plan, every file, and what `SKILL.md` actually tells Claude. `approve` re-hashes the staged tree against a record **this machine** wrote, so a repository cannot commit its own pre-approval. Removal is per **unit**: a component whose recorded files all still match is removed whole, and one you have edited is kept whole — never stripped down to the files you did not touch. Every install, quarantine and removal appends to `.web-chat/packs/audit.log` with its actor.

  A **built-in component name is refused outright**, in either tier, for either actor, with no override: `seedBuiltins` only repairs a directory whose `meta.json` says `builtin`, so a pack shadowing `git-dashboard` would have won permanently. Your own same-named component is never silently replaced (`--replace` is terminal-only), and a pack's `service.js` is unapproved by construction — consent is keyed to the file's hash, so a fresh one still waits for `claude-web-chat trust`. The honest limit is written down in `docs/component-packs.md` and at the head of `lib/server/routes/packs.js`: the install endpoint is reachable by any pane script and **cannot tell a pane's `fetch` from a user's click**.
- **`gh` is used to fetch a pack when it is on your PATH and logged in.** A component library can be private, and the plain HTTPS path cannot reach one: it authenticates only if `GITHUB_TOKEN` happens to be exported, and even then a bare token does not carry the SAML/SSO authorization an organization requires — which the credential `gh` already holds does. When `gh` is available it resolves the commit, reads the release, and streams the tarball; it also lifts the anonymous 60-requests/hour/IP API limit that a couple of installs can exhaust. Without `gh`, nothing changes — the HTTPS path is untouched and remains the fallback.

  Scoped the same way `Authorization` is: **your `gh` credential is only ever spent on github.com**, or on an enterprise host you configured yourself via `GH_HOST`. A pack URL is pasted by whoever asked for the install — and on the surface that can be a pane script — so an arbitrary host never gets it. `WEB_CHAT_NO_GH=1` forces the plain path. Which transport ran is recorded in the pack's provenance and shown in `pack list` and the drawer.
- **The `＋` drawer is now the components *and* packs manager**, with Library and Manage tabs — tabs rather than stacked sections, so an install form never pushes the hot path (spawn a pane) below the fold. Rows carry chips for `built-in`, tier, `service` (and *needs approval* when one is waiting), `seed`, `form` and shadowing; a row spawns into a **stable slot** so panes stop stacking forever, with `⧉` for a second copy. Install leads with *Download for review*; *Install now* is secondary and takes a second, deliberate click for a URL that was never reviewed.
- **The surface has a first-run state.** `#main` used to be literally empty on first open — every other panel in the app has a considered empty state, and the one thing every new user sees first had none. It now says what the surface is, offers a prompt to paste, and names the four keys that matter (palette, component library, graph, push).
- **`claude-web-chat ls`** — every surface running on this machine, which project each one is, and on what port. The daemon is one-per-project and its port walks upward from 5173, so this was previously unanswerable; the registry the capture hub keeps already had it. `--reap` stops the ones that aren't the current project and clears stale entries.
- **`npm test`, and CI.** The suite had never run anywhere but a maintainer's Mac and nothing had ever verified Linux. `npm test` is now the correct entry point (the obvious `node --test test/` misresolves), and GitHub Actions runs it on Ubuntu and macOS across Node 18/20/22.
- **The connected-browser count is exposed** on `/api/health`. It was already tracked for the service supervisor and never surfaced, so Claude could render into a surface nobody had open, say "take a look", and be told it worked.
- **`install` writes `.web-chat/` into `.gitignore`.** Three docs already stated it was gitignored and nothing ever wrote the line, so a project was one `git add -A` from committing its graph, portfile and drafts. Idempotent, and it respects a rule you already wrote.

### Changed
- **Installing a skill no longer claims to need a Claude Code restart.** `docs/component-packs.md` stated that components are picked up live and skills are not. Checked against Claude Code 2.1.243: a `SKILL.md` written into `.claude/skills/<name>/` mid-session becomes available on its own within a few seconds, with no `/exit` and reopen. (A `.mcp.json` change still does need one — that really is read only at session start.)
- **The `UserPromptSubmit` hook no longer claims the render tools will fail.** It said so whenever the daemon was down — but the MCP client auto-spawns and the call succeeds, so the hook was talking Claude out of using the surface on exactly the turns that needed it, on the strength of a false claim. It now reports the thing it never checked: whether a browser is actually watching.
- `install`'s next steps lead with the ordinary path (restart Claude Code, then `claude-web-chat open`) and present Channels as the optional research preview it is.
- `status` reports the real channel state — connected, or parked-until-your-next-message — instead of inferring it from project wiring.
- Server tests sandbox `HOME`, so the suite no longer writes the developer's real `~/.web-chat`.

## [0.5.0] - 2026-08-24

Written up after the fact. 0.5.0 was cut three hours before 0.6.0, its version bump carried the distribution rewrite and touched no changelog, and the `[Unreleased]` block it shipped was relabelled `[0.6.0]` that same evening — so everything else from 0.4.0 → 0.5.0 is recorded in the 0.6.0 section below, and what follows is what 0.5.0 added on top of it. Reconstructed from the commit that bumped the version and the tree it produced.

### Added

- **Distribution became GitHub Releases, and npm stopped being involved at any point.** `install.sh` is POSIX `sh` with no npm in it: resolve the latest release, download the tarball, **verify its SHA256 before unpacking anything**, stage it and move it into `~/.web-chat/versions/<version>/`, swap the `current` symlink atomically, link the three commands into `~/.local/bin`, prune to the three newest versions. No sudo, nothing outside your home, safe to re-run, and a download that dies midway leaves the previous `current` untouched. The motivating failure: a global npm install is a shared mutable directory, so an unrelated `npm i -g` silently replaced a maintainer's `npm link` with a copy of a 16-day-old build — on PATH, invisible, while every test in the checkout stayed green.
- **`claude-web-chat version`** — the version, and *where it came from*: the install kind (a managed release, a git checkout, or an unmanaged leftover), the tree actually running, what `~/.web-chat/current` points at, and a MISMATCH block when the `claude-web-chat` on PATH resolves somewhere else. That last signal is precisely what was missing while the stale binary above went unnoticed for two weeks.
- **`update --to <version>` rolls back from disk with no network**, `update --list` names the versions that are on disk, and **`update` refuses to run from a git checkout** — or any other copy it did not install — telling you to use git instead, because overwriting a checkout with a release tarball would throw the work away.
- **`claude-web-chat uninstall --self`** removes the program itself rather than only this project's wiring, and preserves every project's graph while doing it.
- **`scripts/build-release.js` and `.github/workflows/release.yml`.** The build produces a self-contained `claude-web-chat-<version>.tar.gz` — the `files` allowlist plus *production* `node_modules`, since there are four runtime dependencies and a source-only tarball dies on `Cannot find module 'express'` — alongside `SHA256SUMS`, with every varying field pinned (mtime, uid/gid, entry order, modes) so the checksum is reproducible. On a `v*` tag CI builds it, unpacks it into a scratch `HOME`, runs the CLI out of it, and only then attaches both files to the release.

### Changed

- **`stop` asks the daemon to shut down instead of signalling it and hoping.** `POST /api/shutdown` runs the same `gracefulShutdown` the idle timer uses — drain in-flight requests, wait out a live turn lock, stop services, snapshot uncommitted surface state to `draft.json` — and acknowledges *before* exiting, since responding after the drain deadlocks the shutdown on its own request. `stop` asks, waits up to 40 s and falls back to `SIGTERM` only if the request itself fails; escalating earlier would abort the snapshot it had just asked for. `restart` calls `stop` rather than carrying a second copy of kill-and-wait. The route is closed to browsers — it refuses anything carrying browser fetch metadata and requires a custom header — so no page script can stop your daemon.
- **`update` loads the restart it is about to perform out of `versions/<target>/` explicitly.** Reaching it through `~/.web-chat/current` hands back the *old* module (Node caches by realpath, and `current` was already resolved when the bin was invoked), so every update would otherwise have restarted the code it had just replaced.
- **Windows means WSL2, said plainly in the README** rather than half-supported.

## [0.3.0] - 2026-07-12

### Added
